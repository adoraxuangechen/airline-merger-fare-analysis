# Airline Merger Fare Analysis

Python analysis of route-level fares around the Delta–Northwest merger, using a DB1B-derived market-summary dataset covering 2005–2010.

**Author:** Xuange (Adora) Chen · **[Project page](https://xuangechen.com/)**

This repository provides the analysis-stage replication workflow: processed market summaries → route-quarter panel → fixed-effects estimates and diagnostics → figures and tables.

## Research question and approach

How do fare patterns differ between routes with pre-merger Delta/Northwest overlap and comparison routes?

The workflow constructs passenger-weighted route-quarter fares and defines exposure using 2007 carrier presence. Difference-in-differences and event-study specifications use log fares, route and quarter fixed effects, and route-clustered standard errors. Sensitivity checks examine fixed pre-period passenger weights, matching on pre-merger characteristics, a balanced panel, alternative route definitions, and exclusions around merger and financial-crisis periods.

## Main Findings

- **Pre-merger trends differ across the groups.** These differences weaken the parallel-trends assumption needed to interpret the post-merger comparison causally.
- **Post-merger coefficients are descriptive contrasts.** They should not be read as an identified causal effect of the merger or as evidence establishing coordination or collusion.
- **Sample definitions matter for interpretation.** Alternative route definitions target different populations; comparisons across specifications must account for these differences.

These takeaways summarize the project's interpretation. Numerical estimates and diagnostics are generated by the scripts; stored result tables are not included in this repository.

## Data and replication scope

The workflow reproduces the **analysis stage from a processed DB1B-derived market-summary dataset**. It does not include the upstream construction of that dataset from raw Bureau of Transportation Statistics (BTS) downloads.

Input rows are market/carrier/service summaries, not individual tickets. Airport pairs are treated as directed routes. The analysis therefore does not establish ticket-level fare dispersion, and fare contrasts alone do not identify a coordination mechanism. Pre-period trend differences remain a limitation on causal interpretation even with fixed effects and sensitivity checks.

## Contents

- `run_analysis.py`: runs the analysis pipeline from the supplied processed dataset through figures and tables.
- `inspect_data.py`: checks schema, missingness, duplicate keys and input hash.
- `prepare.py`: constructs the route-quarter panel and exposure classifications.
- `estimator.py`: implements route fixed effects through a within transformation, with quarter indicators and route-clustered standard errors. Its baseline DID coefficient is numerically checked in `estimate.py` against an explicit dummy-variable regression on a small actual-data subset.
- `estimate.py`: baseline estimates, event studies, weighting and matching checks, sample and period sensitivity checks, and the estimator equivalence check.
- `check_scope.py` and `check_full_panel.py`: alternative sample definitions.
- `make_figures.py`: produces figures and LaTeX result tables.
- `environment.json`: environment recorded in the September 2026 source package.

## Run locally

Use Python 3.12 and install the recorded dependencies:

```sh
python -m pip install -r requirements.txt
python run_analysis.py --input "/path/to/DB1B_2005_2010.csv"
```

The input dataset is **not included**. Required columns are `yr`, `qtr`, `cr1`, `cr2`, `cop`, `ap1`, `ap2`, `pax`, `avprc`, `nsdst`, and `avdst`. Supply the same preprocessed DB1B-derived schema used by this project; an arbitrary raw BTS download is not a drop-in replacement. Airport pairs are treated as directed routes. See `prepare.py` for the precise carrier and service definitions.

Outputs are written alongside the scripts and excluded from version control: panel data, classifications, audit summaries, regression results, figures, and table fragments. Running on a different input may change results or invalidate assumptions.
